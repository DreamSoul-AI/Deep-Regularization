# R66：旧 WN 高维 XOR 的来源、实现差异与候选入选审计

2026-09-17。状态：`diagnostic / completed read-only audit`。用户明确批准执行整个 XOR/Ring 计划；本轮完成源码/旧结果核查及掩码候选的无训练筛查。未训练、未推理、未生成 benchmark 数据，累计已审计 selector 仍为3744。取消的 Ring baseline 重跑和专门比较没有恢复。

## 1. 结果与决定

1. **原先优先考虑的掩码候选不入选训练。** 在48条已有 R63 XOR 轨迹、240个阶段边界上，按保留旧代码的 `mask_by_z_final` 规则计算，所有掩码都是全1。前四阶段 raw factor 的绝对值均高于0.01；最后的 z 也全非零。因此单独插入这套操作、保持其余当前流程不变，是无效操作，无需重新训练来确认。
2. **旧高维结果存在，但并未建立精确运行源码身份。** 五份历史文件的24个已完成任务维度格、144条逐折输出与运行日志一致。可追溯 Git 中，运行日期之前的已提交模型文件尚无 `GatedWeightNormMLP`；相关实现首次出现在更晚提交。结果文件没有源码/完整环境/数据哈希或逐阶段 checkpoint。保留源码可分析，不能冒充已经认证的2026-05-04运行时源码。
3. **旧记录将注意力引向 legacy WN 开关，而非单独掩码。** 同日旧 base 与带 `wn_mode=legacy` 的p512记录分别为1/12与10/12；二者均记录 `mask_by_z_final`。旧 base 的 `wn_mode` 字段缺失，故不能严格确认其运行时模式或单因素配对。保留代码中的 legacy 开关同时改变前向尺度、惩罚分数与最终读出，不能把这10/12归因给一个步骤。
4. **本批未选定可训练候选。** 掩码已由现有状态排除；普通时长、重置、旧C等方向已有部分负证据；旧逐坐标惩罚与近似更新属于数学流程差异，不能作为一个未经说明的“恢复旧版”开关塞入当前有效门方法。按照计划“不足两项不凑数”，此轮停在候选入选关口，不自动开启96条训练或独立确认。

这里完成的是核查与排除一个候选，不是达到“XOR追平LassoNet、Ring不退化”的性能目标。历史效果不撤销；主方法、Five-v1版本与默认没有修改。

## 4. 保留实现与当前两版本的真实区别

| 项目 | 保留 WN-legacy 实现 | 当前 Base / Five-v1 | 可支持的解释 |
|---|---|---|---|
| 输入 | raw输入；训练折StandardScaler | Base raw；Five加父特征共享gate的局部平方 | WN高维文件不等于Run8 full-poly2 |
| 前向第一层 | `(x*s*a) @ (W/a)`，a为安全列范数 | Base也具有有效坐标g=a*s；Five为父block范数 | 同参数、默认谱尺度下，raw第一层均化简为`(x*s) @ W`；不是新方法失去了raw XOR表达式 |
| 初始化 | 默认随机Linear/Kaiming，s=1 | Base将列范数归一到1；Five恢复raw维度下默认权重，平方列0 | Five已恢复部分幅度设置，但非旧整套流程 |
| dropout / WD | WN类一处隐藏dropout=.043；非gate WD=.001 | Base均0；Five隐藏.043、非gate WD=.001 | 不混用full-poly2类的双位置dropout描述 |
| 共识与惩罚 | 默认raw gate共识，列范数作为逐坐标惩罚分数；旧顺序收缩再缩放 | 当前g共识、全局C、canonical signed RatioNorm prox | 数学坐标和更新均不同，不只是参数名称 |
| warm与训练阶段 | helper明确每阶段warm20，5×50 ADMM；按保留实现应共350轮 | 一次warm20 +5×20 ADMM，共120轮 | metadata的warm20不能未经核查解释成总共只有20轮warm |
| C | metadata序列先按p/128缩放并截断到5；p256为.2/.4/1/2/4，p512为.4/.8/2/4/5 | .05/.2/.8/3.2/12.8，不做该维度缩放 | 上述旧数值是对保留代码的条件推算，不是恢复出的运行轨迹 |
| rho / 状态 | 默认rho初值200、adaptive_rho=True；跨阶段保留模型、重置Adam/z/u | rho50固定；五阶段Adam/z/u连续 | 不能把metadata外默认当作已记录的五月状态 |
| 阶段操作 | 前4阶段按raw gate绝对值0.01阈值；末阶段按z非零掩码 | 无这类阶段写回 | 末次z掩码后无下一阶段，不能解释为让后续训练避开噪声 |
| 最终排名 | legacy包装层读abs(s*a)，旧NumPy argsort可补零分坐标 | 按非零有效gate Top-k，并列index升序 | 排名语义与零分处理也要对齐 |
| 数据身份 | seed42，保留sweep用不shuffle的KFold、逐折置换及fold seed+1009*(fold+1) | R61/R62多实例、分层shuffle六折；R63又共同内层90%fit | 当前结果差异不是仅替换算法的配对下降 |

上表来源是[源位置证据](../../results/ablation/legacy_wn_highdim_source_r66_20260917/audit.json)中的17项定位、AST提取的helper调用和阶段默认值，以及既有[R61/R62/R63协议](../plans/PLAN_20260915_FIVE_FULL_GRID_R62_XOR_PATH_R63.md)。当前定义仍以[有效门定义](SCHEME_A_FORMAL_MATHEMATICAL_SPECIFICATION_20260820.md)为准；上表没有把旧score加权写成同一个目标。

## 5. 掩码候选：240个边界上均不改变当前轨迹

读取R63 p256/p512 ×Base/Five ×2实例×6折的全部48个已保存checkpoint。只做CPU张量读取、数值比较与排序，不构造模型或执行前向。

先重算原最终Top2，再计算最终 `abs(g) * 1[z != 0]` 的非零Top2；随后检查ADMM第20/40/60/80轮的raw factor阈值，以及第100轮的z支持。这里严格按保留旧操作检查raw factor阈值，不擅自把0.01改成对有效g的阈值。

| p | 方法 | 原命中数 | 终点掩码后 | 前四阶段最小abs(raw factor) | 100轮中最小z支持 | 触发的阶段掩码 |
|---|---|---:|---:|---:|---:|---:|
| 256 | Base | 11/24 | 11/24 | 0.773825 | 256 | 0/60 |
| 256 | Five-v1 | 3/24 | 3/24 | 0.752997 | 256 | 0/60 |
| 512 | Base | 0/24 | 0/24 | 0.797584 | 512 | 0/60 |
| 512 | Five-v1 | 0/24 | 0/24 | 0.653800 | 512 | 0/60 |

四组共4800个已记录ADMM epoch的z均没有零坐标。此前“z可以稀疏”是变量一般性质，不能据此假设这些120轮高维轨迹已经产生了稀疏支持。R64长尾终点也不能替代这里的原120轮状态。

**为何无需GPU重训这项单独改动：** 在其余模型、优化器、C路径、随机数和更新次序完全不变的前提下，第一个新增掩码全1，因此参数不变；下一段沿原轨迹到第二个全1掩码，依次可推出五个边界均不改变训练与结果。该结论仅适用于插入这套确定的掩码、无其它副作用；不覆盖另外更换阈值坐标、状态重置、C路径或整个旧训练器。

逐边界记录也保留了“若改为有效g阈值0.01会屏蔽多少项”，但不把这种不同操作当作旧版原样恢复，更未据真值选择新阈值。见[阶段算术](../../results/ablation/legacy_wn_highdim_source_r66_20260917/phase_mask_arithmetic.json)。

## 6. 候选入选表与停止位置

| 方向 | 本轮决定 | 理由 |
|---|---|---|
| 单独恢复保留旧掩码规则 | 排除本批训练 | 48条XOR轨迹上的240次操作全为恒等；XOR无法因此提高 |
| 把阈值从raw factor换为有效g，或另调阈值 | 不入选 | 已是新的定义/取值，不能借旧metadata给它来源；本轮未建立针对性理由 |
| 直接延长阶段、取消warm、重置Adam/z/u、换旧C | 不自动入选 | R1/R34/R43、R2/R35、R25–R27/R37–R42、R40/R45已有部分负证据；缺少新的具体机制证据 |
| 完整搬回WN-legacy | 不作为单因素候选 | 运行源码身份未闭合；前向/惩罚/训练生命周期/读出等同时变化 |
| 将旧C/score或旧近似收缩塞进当前方法 | 不执行 | 改变正则/更新语义，不能声称仍是当前全局C的规范有效门方法；本轮无这样的明确候选定义 |
| 每阶段重新warm-up | 保留为未验证差异，不入选本批 | 已发现保留helper如此实现，但尚无证据把它与旧高维收益单独联系；不能把未测自动当作优先候选 |

“没有候选入选”不表示所有可能改法都无效，也不表示网络无法学习XOR。本轮支持收窄解释：旧记录的高维成功不能直接归功于最终掩码；raw前向表达形式也不是唯一差别。下一研究问题若转向正则坐标或联合更新，应先给出明确数学定义与可区分假设，再形成新的有限候选，不能悄悄恢复整个旧算法。
