# 原方案复现与候选一 Ranking 对照

原公开实现已在128维四任务上完成复现。按原500轮、120轮 warm-up 和6折协议，原列范数 scaling 的四任务平均 recall@k 为75%，一阶与一阶加经验 Fisher 二阶均为71.875%。二阶方案没有改善本轮 Top-k 命中数，相比原方案低3.125个百分点。连续排名也不是完全相同：加入二阶后，平均 AP 与恢复 AUROC 略降，不能得出“总不会差”的判断。

复核日期为2026年11月28日。本记录只涉及候选一和 ranking，不涉及下游重训、候选二至四或超参数搜索。上一轮[缩短预算初测](<2026年11月27日 候选一 Ranking 初测.md>)保留为独立记录，不与本轮数据混算。

## 原方案与复现边界

本轮“原方案”明确指公开的 `feature-selection@555ba11e8872bd6618cd721bd3b08f7128db9e6b` 中 `src/admm_input_group_wrapper.py` 的共享直接 gate、列范数调节阈值与两变量 Ratio ADMM 路径。它不是9月历史报告中带有效 gate 的 GRN-FS Base，也不是完整多项式 Legacy-poly2 或五项组合 Five-v1。未取得的11月未提交代码不能被此复现替代。

[原入口](https://github.com/DreamSoul-AI/Deep-Regularization/blob/555ba11e8872bd6618cd721bd3b08f7128db9e6b/experiments/main/run_admm_input_group_benchmark.py) 定义数据、划分与默认参数，[原模型和训练](https://github.com/DreamSoul-AI/Deep-Regularization/blob/555ba11e8872bd6618cd721bd3b08f7128db9e6b/src/admm_input_group_wrapper.py) 定义前向、损失与 ADMM。复现入口通过 [固定源码加载器](../../experiments/legacy_ranking_reference.py) 从本地 Git 对象提取原定义，直接执行未改写的原训练函数。数据集类使用行为等价的 TensorDataset 适配，去除无关第三方导入；未安装历史全套依赖。

每个任务的每个折均另外训练原始源码参照，再与移植后的原方案逐参数比较，24个比较全部为完全一致，最大参数差为0。这证明当前 CPU 环境中所选原训练路径已对齐，不代表逐字节恢复历史机器、旧 PyTorch 版本或全部历史结果。

### 从初测到严格复现的修正

初测有意缩短到120轮、40轮 warm-up，但还使用了分层划分、不同种子、一次全局特征置换、独立的 shuffle 随机生成器及更稳定的三次方程计算，不能充当原入口的严格复现。本轮增加独立 `protocol="legacy"` 模式，保留初测设置，不覆盖其证据。

原500轮参数核对还暴露了浮点结合顺序差异：原对偶更新是 `(u+g)-z`，移植的 `u+(g-z)` 数学等价，但 float32 长轨迹会分叉。首次核验未通过便停止，失败产物留在本机，未写入结果表。修正仅作用于 legacy 模式，再核验500轮达到参数完全一致，之后才完成全部配对比较。

## 本轮固定设置

| 项目 | 本轮设置 |
| --- | --- |
| 任务 | XOR、Ring、Ring+XOR、Ring+XOR+Sum |
| 样本与输入 | 每任务1000样本、128维，真实支持数分别为2、2、4、6 |
| 数据与模型种子 | 每个任务重置 NumPy seed=0，每次训练重置 torch seed=0 |
| 预处理 | 原生成器含 knockoff 随机数消耗，X先映射到[-1,1]；标准化只拟合当前训练折，使用原 NumPy float64 算术后转 float32 |
| 划分与置换 | 原 KFold(6)，不 shuffle；每折按连续 NumPy 随机状态重新置换列，并保存真实支持 |
| 训练 | 500轮，其中120轮 warm-up；batch size=64；两层32宽 Mish |
| 优化器 | Adam，lr=0.005，weight_decay=0.001；进入 ADMM 时重置优化器 |
| 稀疏更新 | C=0.05、初始ρ=50、原残差平衡与原 float32 三次方程更新 |
| stochastic regularization | feature dropout=0.6，网络 dropout=0.04308691548552568 |
| 新 score | 固定128条训练行、每10个 ADMM epoch 刷新、每批32行；聚合有符号项后取绝对值，再按均值归一为 scaling |
| 比较与读出 | 原列范数、纯一阶、一阶＋经验 Fisher 二阶；统一按最终原 gate 绝对值排序 |
| 执行环境 | CPU、2线程；Python 3.13.9、PyTorch 2.11.0+cu130、NumPy 2.3.5 |

原列范数路径每轮刷新，无新增归一化。新两种 score 使用相同的校准样本、刷新频率、归一化和训练随机流，因而一阶对二阶的比较固定了这些条件。新方法相对原方法的差异也包含 score 的映射及刷新方式，不能把全部差距只归因于二阶项。

本轮只用原预算、固定参数和最后一轮，不按真值支持、测试损失或最终表选 checkpoint，不为改进结果而调 λ。新 score 参数沿初测固定，未进行本轮结果驱动的搜索。数据生成器与模型核心代码哈希保存在 [清单](<20261128 原方案复现 Ranking 证据/manifest.json>)。

主指标是 recall@k，表中为6折均值。四任务平均对任务等权，不因 k 或输入维度改变权重。

| 任务 | 原列范数方案 | 一阶 | 一阶＋二阶 |
| --- | ---: | ---: | ---: |
| XOR | 100.00% | 100.00% | 100.00% |
| Ring | 75.00% | 66.67% | 66.67% |
| Ring+XOR | 58.33% | 54.17% | 54.17% |
| Ring+XOR+Sum | 66.67% | 66.67% | 66.67% |
| 四任务平均 | 75.00% | 71.875% | 71.875% |

对原方案，一阶加二阶在24个折中1次胜、20次平、3次负。对纯一阶，24个折的 Top-k 命中数均相同，但5个折选出的特征集合不同，24个最终 gate 向量全部不同。不能把“命中数相同”写成“代码没有起作用”或“整个排名相同”。

## 为什么看起来差不多

这里分别检查固定模型评分和 score 反馈训练，不能混成同一种改进。

对复现后的原模型，使用相同128条校准训练行计算一阶与一阶加二阶 score，跨特征排名的 Spearman 相关系数在0.999914到1之间。二阶项总量与一阶绝对值总量之比约为5.5%到16.8%。这些终点诊断说明本批模型上二阶修正很少改变直接评分次序，但不能由此推断每轮反馈过程都一样，也不能说二阶没有信号。

固定同一个原模型、只更换最终读出时，Ring 的平均 recall@2 从一阶 score 的66.67%变成二阶 score 的75%；但将 score 接回训练后，两种方案都为66.67%。因此只在训练后更换排序和通过 score 改变稀疏更新，需要分开评价。这一观察只覆盖本轮固定实例。

一阶加二阶没有必然不退化的数学保证。二阶项虽非负，但先与有符号一阶项相加、再取绝对值，可能发生抵消及重排；经验 Fisher 也不等于真实删除损失的 Hessian。score 还会通过阈值改变训练轨迹，没有保留原解并按独立准则回退的机制。
