# Baseline 修复与512维复核

mRMR 已解决本机编译依赖及两个旧 Python 接口问题。新增 LassoFlexNet 数值输入、二分类的本地实现，完成128维四任务和512维 XOR/Ring 的固定设置 ranking 比较。该实现明确登记为论文文本的可行变体，不能冒充作者代码或完整论文复现。

更关键的版本核对结果是：此前75%的四任务均值属于公开 raw-gate 快照的500/120轮协议，并非10月报告中的有效 gate GRN-FS。此次公开快照在512维 XOR 上成功，也不能据此宣布历史高维失败已经修复。

## 一、飞书文件夹与历史高维结果

已读取 [Deep Regularization 项目文件夹](https://dreamsoul.feishu.cn/drive/folder/Paief0K19lmyoEdKeLtchLtUn9f)、会议总结及其会议记录子目录、论文子目录。找到实验报告和数学定义；在这些目录及相关报告正文中未发现可运行的源码包、notebook、代码附件或11月27日 A—L 完整结果表。这一结论不扩展为整个飞书都没有代码。

- [10月9日实验进展](https://my.feishu.cn/docx/AXzzdP73Go5VhUxIdw7coClanEb)：共享 x/x² 父 gate、32×32 ReLU、120轮、无 warm-up 的有效 gate 版本。10月3日固定 trial8 的512维 Ring 为95.8%，XOR为4.2%；每格2个新实例×6折。参考参数 C≈0.003172、ρ≈0.18857、lr≈0.002084。后续调整仍记录 XOR 困难；不能只凭当前公开快照的成功否定该记录。
- [GRN-FS 数学定义与推导](https://dreamsoul.feishu.cn/docx/Bxa7dPa32oF4hvxwk1Pcnm3Pnvf)：有效 gate 为 g_j=‖w_j‖₂s_j，前向、正则、ADMM 一致性和最终排序都用 g；比值正则采用 canonical coupled prox，零点定义 R(0)=1。公开 raw-gate 的 ADMM 变量与旧 shrink/cubic 更新不等同于此定义。
- [11月27日会议纪要](https://dreamsoul.feishu.cn/docx/K9lNdOS8dohOCQxlzaUcFzawn4t)及 [原始会议记录](https://dreamsoul.feishu.cn/docx/S7nOdBo1noifBLxlYcAcrQrenLf)明确提到512维 XOR 和 A—L 对照，但未保存对应源码身份和屏幕数值表。
- 更早的 [9月研究证据](../research/20260920-xor-ring-thread/README.md) 中 Base/Five 的512维 XOR 失败是另一组版本。旧 Five、10月共享平方版本、11月 A—L 和本次 raw-gate 必须分开报告。

因未取得10月/11月代码，本轮没有声称精确复现它们。下一步最值得做的是按数学定义和10月报告重建一个明确命名的有效 gate 参照，先核验 canonical prox 和训练协议，再比较一阶/Fisher；该重建目前未执行。

## 三、512维有界复核

公开 raw-gate 在 XOR 上三种 scaling 都为100%；Ring 中一阶/Fisher 均低于原列范数。加入二阶不保证不退步，本轮一阶与Fisher的 Top-k 相同，连续排名 AP 不同。原列范数与新梯度 scaling 还存在数值归一化差异：新 score 映射到均值1，原列范数保留原尺度。因此不能将差距全部归因于梯度或二阶信息本身；需要后续尺度控制才能作机制判断。

LassoNet 沿用128维包装器的32×32结构、30/30轮分阶段上限和原生 λ 路径/内部验证选模，在CPU完成12折；不等同于历史报告中更长路径的 LassoNet。原快照500轮也不是和所有 baseline 等预算的比较。公开参照逐参数对齐12折，48个 checkpoint 重载及36条评分重算均通过；这些验证证明本轮指定实现与记录一致，不能补上当前有效 gate 版本的源码缺口。

## 四、mRMR 的实际修复与排名读出

使用 pymrmre==1.0.7。本机缺少可用 MSVC；安装 Microsoft 签名的 VS2022 Build Tools C++ 工具及 Windows11 SDK26100，使用较短安装路径，成功构建 cp313 Windows wheel，无需重启。安装只进入独立 baseline 环境；wheel SHA-256 为 `49f0db24af79033a73ccbfdf6e92907bff2a06ee4cdcb939ebc426ac85fcbb2e`。

编译后另有两处兼容错误：NumPy 空 priors 数组不能直接作布尔值；Pandas2 已移除 iteritems。修复脚本 [patch_pymrmre.py](../../experiments/patch_pymrmre.py) 只修改这两处 Python 包装代码，保留原生 C++ 算法，记录修改前后哈希及本地备份。未修改全局 Python 环境。

旧包装器只返回选中集合，再用随机扰动拼完整排名，不能用于可信的 AP。新增 mrmr_fullrank 从原生 mrmr_ensemble 读取 solution_length=D、solution_count=1 的完整贪心顺序，以 D-rank 为分数。128维24折的 Top-k 集合与原 k 长度调用完全相同；AP 读出改进没有改变这些选中集合。

本版本默认使用 Pearson/Gaussian-MI 近似，不等于离散非线性互信息的另一种 mRMR 实现。XOR/Ring 差的结果仅适用于该估计器和本轮协议，不能推广为所有 mRMR 都无效。

可在已配置 MSVC 的 Developer PowerShell 中安装 Cython、NumPy 等构建依赖后运行 `python -m pip install pymrmre==1.0.7 --no-build-isolation`，随后运行 `python experiments/patch_pymrmre.py --record-dir .tmp/mrmr-patch`。Windows 本机须先导入 torch 再导入 NumPy/SciPy/sklearn；本轮安装时通过命令级 PYTHONPATH 的 bootstrap 保持该顺序，不更改全局环境变量。完整环境和产物留在本地 `.tmp/`。

## 五、LassoFlexNet 实现范围与算法歧义

依据 [官方论文](https://proceedings.mlr.press/v306/lui26a.html) §4–5、算法1–2、附录C、图8、表5和 λ 路径说明核对；[作者仓库](https://github.com/BorealisAI/lassoflexnet) 本轮仍无可运行代码。实现入口为 [模型](../../src/lassoflexnet.py)、[训练与排名](../../experiments/ranking_lassoflexnet.py)、[checkpoint 核验](../../experiments/verify_lassoflexnet.py)。

实现包括仅在内部训练子集拟合的决策树 PLE 分箱、独立 per-feature ResNet、无 affine 的 BatchNorm、标量 skip β 和 MLP-Mixer。图8明确要求第一层 feature-mixing 无输入 LayerNorm/残差，embedding-mixing 仍保留 LayerNorm/残差。最终 v2 按此区分；早期 v1 试跑仅保留本地诊断，不进入本表。第一 feature-mixing 列与 β 同时为零时，无其他残差绕过该特征。

印刷算法2的字面更新不总满足 hierarchy：β̄=0、W̄=3、λ=1、M=1 时得到 β=0、W=1。代码保留 paper_literal 模式以重现这一问题。128维 XOR 首折的完整路径诊断选中 checkpoint 违反量为0.0920238，模型重载验证通过；该诊断不混入主表。

主表采用 sequential_feasible：先 soft-threshold EMA β，再对 EMA W soft-threshold 并投影到逐列 ±M|β_j| 的盒约束。这是按正文两个顺序子问题实现的可行本地变体，不能声称已经还原作者未公开的优化器，也不是联合问题的精确全局解。

固定参数：PLE最多8叶；PFE宽8、2个残差层、embedding8；Mixer2块、hidden64、dropout0.1、τ0.1、M10；AdamW lr0.001、weight decay1e-5、batch512；稠密预训练最多200轮，12个正 λ 路径点每点最多100轮，patience20；λ从1e-7到0.001，幂路径0.5；EMA0.99。未明确到实现细节的选择，包括 EMA 顺序/衰减、路径点数、W惩罚与β共用 λ，均作为本地冻结参数记录，不称为作者默认。

每折内部80/20分层划分，PLE仅使用内部fit标签；模型按正 λ 路径中最低验证BCE选取，最终按 |β| 排名，稠密预训练分数另作诊断。主表只支持数值输入、二分类，未实现类别输入、多分类或候选四 ADMM/PQI。

36个正式 checkpoint 全部重载，分箱buffer、数据哈希、β分数、正 λ 路径选模一致；CPU复算验证BCE最大差1.20e-7。正式 feasible 路径的每次更新均检查 hierarchy；所选模型违反量为0。存在实际零β的3个模型还核验了改变对应原始特征后预测完全不变，其余模型不冒充实际零特征检查。
